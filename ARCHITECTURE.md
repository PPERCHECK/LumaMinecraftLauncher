# Архитектура Luma

## Выбор стека

Electron обеспечивает Windows-приложение, системные диалоги, запуск Java и safeStorage/DPAPI без необходимости устанавливать Node.js пользователю. React + TypeScript отвечают за интерфейс. Vite собирает renderer; esbuild собирает main/preload. Игровой запуск и обработка наследования версий выполняются XMCL Core, загрузчики устанавливает XMCL Installer. Файлы игры скачивает собственный HTTPS-слой с проверкой контрольных сумм, повторами и ограничением параллелизма.

Версии XMCL зафиксированы в lockfile. У более нового опубликованного пакета при разработке обнаружена зависимость `workspace:^*`, несовместимая с обычным npm install. Используется рабочий installer 5.4.0 / core 2.13.0; транзитивный undici обновлён override до 6.29.1. adm-zip 0.6.1. Результат аудита production-зависимостей указан в VERIFICATION.md.

## Границы процессов

```text
React renderer
  │ window.luma.call / window.luma.on
  ▼
preload.cjs — contextBridge, nodeIntegration=false, sandbox=true
  │ IPC с проверкой main frame
  ▼
Electron main / dispatch
  ├── storage      state.json + DPAPI vault
  ├── auth         Microsoft device flow / Ely OAuth / offline UUID
  ├── network      JSON API + очередь + HTTPS-файлы
  ├── minecraft    версии / загрузчики / Java / запуск / логи
  ├── game-files   библиотеки / ресурсы / контрольные суммы
  ├── catalog      Modrinth / CurseForge / зависимости / обновления
  ├── packs        импорт / экспорт / снимки / восстановление
  ├── archive      безопасная распаковка
  └── servers      Minecraft TCP status + DNS SRV
```

Renderer не получает access/refresh tokens, API keys или Ely Client Secret. Он видит только публичные профили и признаки наличия ключей. Вход Microsoft происходит во внешнем браузере; Ely OAuth использует временный loopback HTTP-сервер с проверкой state. Секреты шифруются ОС, фолбэк в открытый текст запрещён.

## Структура исходников

```text
electron/       системные модули и IPC
src/            React-интерфейс, CSS, shared types, векторные иллюстрации
scripts/        dev / build / assets / test / smoke
tests/          значимые тесты путей, архивов, сети и очереди
build/          собственная иконка и векторный логотип
dist/           собранные main.cjs, preload.cjs и UI
release/        упакованное Windows-приложение
```

## Поток установки и запуска

1. Выбирается запись из актуального манифеста Mojang и совместимая версия загрузчика из официальных метаданных.
2. В очередь добавляется операция, связанная с UUID сборки. Изменение её файлов блокируется до завершения операции.
3. Проверяется SHA-1 version JSON, определяется Java major. Пользовательская Java проверяется через `-version`, либо скачивается Adoptium ZIP с SHA-256.
4. Скачиваются client jar, библиотеки, log config, индекс ресурсов и assets. Валидные файлы пропускаются; файлы сначала пишутся во временный `.part`, затем атомарно заменяют целевой файл.
5. При необходимости устанавливается Fabric/Quilt/Forge/NeoForge, затем проверяются его библиотеки.
6. Перед запуском обновляется сетевая сессия аккаунта; для Ely.by подключается authlib-injector.
7. XMCL создаёт аргументы и запускает Java без shell. Рабочая папка сборки отделена от общих ресурсов.
8. stdout/stderr передаются в консоль и файл с редактированием известных токенов. При закрытии процесса записывается время игры.

## Моды и переносимость

Modrinth сохраняет project/version ID, файл, URL и SHA-512. CurseForge сохраняет project/file ID, разрешённый download URL и проверяет доступные SHA-1. Обязательные зависимости проходят тот же установочный путь. Источник показывается в карточке и списке установленных файлов. Перед изменениями модов создаётся ZIP-снимок. Модификации выключаются переименованием файла, без удаления.

Публичные экспорты используют manifest/URL, а не перепаковывают произвольные .jar. Смешанные и ручные сборки переносятся полной локальной копией. Импорт проверяет выход за пределы целевой папки и отклоняет symlink entries. Поддерживаются общий overrides и client-overrides для mrpack, overrides для CurseForge.

## Сохранение состояния

Маленький публичный state пишется через временный файл + rename. Системный vault — отдельный зашифрованный blob. Файлы миров и конфигураций находятся в изолированном каталоге UUID; общий кэш можно повторно использовать между сборками. Приложение допускает один процесс; операции очереди выполняются последовательно, внутри одной установки файлы скачиваются параллельно с лимитом шесть.

Дальнейшие этапы публичного продукта: серверная Ely-интеграция, матрица игровых тестов загрузчиков/исторических версий, безопасная система обновления самого лаунчера и подписанные релизы. Они не имитируются в интерфейсе текущей версии.
